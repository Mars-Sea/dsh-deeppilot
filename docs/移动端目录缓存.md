# 移动端目录缓存

## 一、范围与存放

1. 2026-10-16 用户选择内存与磁盘同时实现，iOS 和 Android 采用相同策略。缓存三种可重建元数据：技能、系统指令、模型目录。权限当前值、命令执行结果、反馈、日志归档、凭据和技能正文不进入此缓存。
2. 键包含配对配置身份、主机地址、主机 audience、设备身份、TLS 指纹、会话和目录种类；主机身份字段组合后散列，不在缓存文件名保存原文。同一会话编号在不同配对身份或主机下不能共享目录。
3. 当前应用身份是配对身份，不是模型供应商账户。供应商凭据不写缓存；上游模型目录变化由刷新及短有效期校验，选择模型时仍由主机判断可用性。
4. iOS 位于应用缓存目录 `Catalogs-v1`，Android 位于应用缓存目录 `catalogs-v1`。每项带版本、键校验和最后成功读取时间；写入采用原子替换。单份磁盘文件最多 3 MiB，最多保留 64 份、合计 16 MiB；内存最多 64 份。应用卸载或系统回收缓存后重新读取。

## 二、何时使用与更新

| 场景 | 行为 |
|---|---|
| 同一身份和连接，成功读取后五分钟内再次打开 | 直接用内存，不重复请求 |
| 首次打开且没有缓存 | 展示加载状态并读取主机 |
| 内存超过五分钟 | 先显示旧目录，后台刷新；不按用户访问延长有效期 |
| 应用重启后的磁盘目录 | 始终视为待确认旧数据，先显示并立即后台刷新；标明正在更新 |
| 手动点击刷新或模型列表下拉刷新 | 绕过有效期，重新读取；正在进行的同一请求仍合并 |
| 技能、命令、预设或工作目录变化通知 | 对相应会话的技能/命令缓存失效，关闭旧原生选择界面并重新读取 |
| 模型当前选择变化通知 | 即时更新当前选择，使该会话模型目录失效；旧加载不能覆盖新选择 |
| 断线重连 | 新连接代次需重新验证；可以显示同一身份的旧目录，不能直接当作新鲜数据 |
| 切换主机或重新配对 | 使用不同命名空间；解除配对/删除实例清理对应磁盘及内存 |
| 读取失败 | 保留最后成功目录，显示上次列表与重试入口；不把错误存成空目录 |

1. 五分钟是按需校验窗口，不启动周期轮询；打开候选、进入会话、打开模型选择器或手动刷新才读取。没有缓存时第一趟网络请求仍然需要等待。
2. 技能和命令并行读取，单独失败不吞掉另一种结果；查询文字变化仍只在本地筛选。相同键、相同连接代次的并发读取共用一个请求，一个界面退出不取消其他调用者所需的数据。
3. 命令发送与权限操作不能依赖旧缓存：执行前重新读取主机目录，原生权限/反馈入口先核对来源，权限执行额外携带定义标识。操作失败保留草稿，不自动重试。
4. 模型目录可跨应用重启恢复，当前选中模型和失败详情不落盘。当前选择优先使用主机投影或刚完成的切换响应，重新加载目录不能把旧选择写回来。`s2c.models.changed` 是新增的可选服务端通知；模型供应商目录没有可靠专用通知时以五分钟按需刷新和手动刷新兜底。

## 三、格式升级与失效屏障

1. 格式版本当前为 1。版本不匹配、文件损坏、键不符、未来时间、超过七天或过大文件按缓存未命中处理，并在成功读取后重建。缓存不是业务数据，不做可能误解字段含义的强制迁移。
2. 失效先同步推进代次并取消旧请求，再清理磁盘。回包和写盘前核对所属键/代次；切换主机、删除配对或刷新期间晚到的响应不能重新成为有效缓存。
3. 元数据磁盘操作在串行后台队列执行；写盘失败不阻断成功的主机请求。缓存没有新增主机侧第二层时间有效期，避免多层缓存把过期时间叠加。

## 四、接口与验证

1. 不新增读取接口，复用 `c2s.session.skills`、`c2s.session.commands`、`c2s.session.models`；新增的 `s2c.models.changed` 来自既有 `modelSelection` 投影。上游全接口及文档盘点见[命令对接说明](移动端命令对接说明.md)。
2. 核心回归覆盖并发合并、空列表、有效期、网络失败保留旧目录、重启、配对/主机/会话隔离、连接变更、请求取消、晚到结果、磁盘格式/损坏/超龄重建。iOS 界面已验证重复打开请求数不增加、手动刷新增加一次、应用终止重启后先显示磁盘目录并完成一次后台读取。
3. Android 核心回归与调试构建通过，模拟器界面证据见 Android《目录缓存验收》。2026-10-16 已在独立官方主机验证模型切换确实发出 `s2c.models.changed`，实际 Android 界面可读取技能/命令与切换模型。真实服务下的缓存请求计数、真机弱网、低磁盘或供应商账户切换仍待验收；未发布。
