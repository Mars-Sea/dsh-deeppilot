# 安全路线图：协议 v2

[English](./SECURITY_ROADMAP.md)

状态：提案，非规范性文档。`PROTOCOL.md` 仍是协议 v1 的 wire contract；本文
记录下一阶段安全升级，不代表这些能力已经实现。

## 为什么需要 v2

协议 v1 使用所有客户端共享的高熵长期 Bearer Token。它很难被在线猜中，但每份
Token 都拥有相同的完整权限。主机无法只撤销一台丢失的手机、验证设备的密码学
身份，也无法在不轮换所有客户端的前提下授予只读权限。

## 目标设计

1. 使用短期、一次性的引导码配对。引导码在五分钟后或首次成功注册后失效，不能
   作为普通会话凭据使用。
2. 在设备支持时生成不可导出的签名密钥（iOS 使用 Secure Enclave，Keychain
   作为回退），主机只保存公钥和经本机用户确认的显示名称。
3. 每次连接使用主机 nonce、设备签名、协议版本、audience 和有界时间戳认证。
   每个 nonce 只能使用一次，并将认证身份绑定到该 WebSocket，以阻止重放。
4. 签名挑战通过后签发短期会话授权。引导码、签名和会话凭据都不得写入 URL。
5. 主机设备记录至少包含公钥指纹、创建时间、最后使用时间、撤销状态和 scope，
   支持即时撤销单台设备而不影响其他手机。
6. 最少拆分为会话只读、发送 Prompt、会话管理、回答审批/问题等权限；未声明
   scope 默认拒绝。对于高影响审批，在 iOS 可执行时要求新的本地生物识别或
   用户在场确认。
7. 安全审计事件使用保护隐私的设备密钥指纹；普通日志不持久化来源 IP、消息正文、
   凭据或原始 APNs Token。

## 迁移与降级规则

- v2 必须显式协商，不能静默改变 v1 的含义。
- v1 客户端可以进入有期限的迁移窗口。设置页必须清楚显示共享 Token 仍处于启用
  状态，并允许所有设备迁移后由本机用户关闭。
- 安装实例关闭 v1 后，远程客户端不能重新启用，也不能从 v2 降级；重新启用旧
  协议只能在主机本地操作。
- 当前 `devices.json` 中仅供展示的记录不是密码学身份，必须重新注册。
- 共享 Token 只保留为迁移/引导输入，最后一台 v1 客户端移除后应删除。

## 发布前必须验证

- 覆盖过期、nonce 重用、签名/audience 不匹配、scope 拒绝、撤销竞态、时钟偏差
  和 v1 降级的单元测试。
- TypeScript 与 Swift 共用的签名和规范化挑战编码测试向量。
- LAN 与 Funnel 两条路径的集成测试，包括重连/恢复、迁移期间轮换 Token、并发
  撤销设备。
- 覆盖连接抖动、畸形密钥/签名、设备表耗尽、重放和多来源地址的滥用测试。
- 主机设备注册表丢失后的恢复流程，以及无法通过 `/phone` 调用的本机恢复入口。

## v2 之外的发布门槛

在把内嵌 helper 描述为生产可用前，需要自动执行依赖漏洞扫描，保持 CodeQL 和
依赖更新检查通过，并对每个分发的 macOS helper 完成签名与公证。签名依赖维护者
的 Developer ID 和公证凭据；只有这些 secret 与发布工作流配置完成后，CI 才能
真正强制该门槛。
